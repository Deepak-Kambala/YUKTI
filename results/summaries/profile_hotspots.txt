READING THIS RESULT
========================================================================
The two measurements bound the answer from opposite sides. Direct
instrumentation under-counts (it times only the two wrapped entry
points, not the simplex's own vector arithmetic around them); cProfile
over-counts small frequently-called functions relative to large ones.
Where they agree, the share is real.

What this does NOT show: that a GPU would be faster. Moving a kernel to
a GPU is worth doing only if the kernel is both dominant AND large
enough to amortise transfer latency. At this instance size the basis
matrices are tiny (tens of rows), so the correct next step is sparse
LU with factorization updates on the CPU -- which removes most of this
cost outright -- before any GPU work. No GPU experiment has been run.
